Groundwork · 4 of 4

The space is finite, and it fills

One 32-bit space for the whole build, about two billion addresses and no more. Two things fill it.

macroseach expansion spends fresh addresses (where the limit first drew attention).
modular buildseach loaded PCM carries its own copy of the files it saw, so a shared header is paid for again and again.

fatal error: ran out of source locations

People hit this on real builds, reported on LLVM Discourse and in GitHub issues. When the space runs out, the build stops.

This patch only takes on the modular side.

Why modules strain it

Why modules strain it · the cause

It only happens when a shared header is not its own module

Included textually, each PCM seals its own copy inside. two, and counting

The fix is a bottom-up layout. Make shared.h a module and import it, so both share the one copy. one, shared

So why isn’t every shared header a module? The ones that hurt are system and third-party headers you don’t own, plus config headers that must stay textual. Teams modularize what they can and leave the rest, which is where the duplication lives.

Two places to intervene

The duplicate can be stopped at either end

Goal: catch the duplicate.

Attempt 1 · reader side
at load

Collapse a copy onto the first as it arrives.

Attempt 2 · writer side
at write

Never write a copy that already exists.

The one thing both attempts rewrite

A stored location is a pair

On disk, a source location is not a raw number. It is a pair: which module owns the file, and the offset into that module’s copy.

module
self
offset
1,420

Our token in module A. module = self means “my own copy”, and 1,420 is where it sits in that copy.

Attempt 1 · at load

Fix it when the modules meet

Duplicates only meet when modules are loaded together, so catch them there.

loaded-files map
shared.h→module A, offset 1,000
types.h→module A, offset 5,890
1As modules load, record each file’s first copy in a map.
2Loading B, shared.h is already in the map from A, so give B’s copy no new space.
3Remap B’s shared.h locations to land in A’s copy.

Attempt 1 keeps the pair at self and maps the offset elsewhere at load, nothing on disk is rewritten. The catch is that B’s file was written assuming its copy owns a clean, unbroken range.

Attempt 1 · the cost that killed it

To find the duplicates, you scan everything

Compile time and peak memory regressed.

The loaded region is reserved up front, before any entry is placed. You cannot reserve, then shrink. So the duplicates must be known before allocating, which means walking every SLoc entry of every module at load.

Clang works the opposite way. An entry is built only when something touches it, and most never are. The scan throws that away, on every module, whether or not anything dedups.

And it is not just the scan. The load path carries the lookup map, the forward and inverse remap, and four per-module tables, all live at once.

Too complex
Attempt 2 · writer side

Prevent the copy instead of repairing it

Attempt 2 never writes the second copy at all. Each shared location just repoints to A’s copy instead. No gap opens, so nothing to remap, scan, or undo.

Clang already does a version of this. A module map kept only to find textual headers is never pointed at in the AST, so the writer drops its source-location space, keeping only the file record.

drop the SLoc entries  // never referenced in the AST
keep a file record  // for dependency scanning

Generalize it from module maps to the headers themselves. When an import already owns the file, drop its entries and point the locations at that owner.

A note on tooling

How I used AI on this

Seeing the invisible
In school the compiler was taught in slides and diagrams, so I could always see what it was doing. Here, even after reading the code, the picture would not come, so I had it drawn out until I could see it.
Tracing the patches
It pulled up the related patches and how module maps got to where they are. That is how I found the change mine builds on.
A sounding board
Brainstorming out loud. We would float ideas and push back on each other, bouncing until something held.
Prototyping fast
Standing up a rough version quickly to see if an idea holds, before committing to it.
Testing, and never the first answer
I would describe a case and it would write the test, with variants I never think of. A test is how I found out if either of us was talking rubbish. Always validate!

One copy is enough

ProblemEvery module carries its own copy of shared headers, and the 32-bit source-location space runs out.
ApproachNever write the second copy. When writing a module, redirect a shared file’s locations to the module that already owns them.
Result−19% loaded location space on ROOT, with compile time and memory steady and one small, understood scan cost.
